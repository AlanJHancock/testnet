## 1. Decompiler IDE Integration

### SIR1 Decompiler + Three-Pane Display
- **Decompile button** added to IDE — sends `.sqb` binary to server `/decompile` endpoint
- Server reconstructs pseudo-SynQ source from the SIR1 IR section of the SQB artifact
- **Three-pane persistent window** below the main IDE panel:
  - Original SynQ (source from SQB SOURCE section)
  - Decompiled SSA (pseudo-SynQ from SIR1 IR)
  - Solidity (transpiled EVM source, if present)
- **Synchronized scrolling** — Original SynQ pane is scroll master, syncs SSA and Solidity panes
- **Syntax-highlighted SSA** — block labels (cyan), phi nodes (orange), value defs (purple), operations (blue), terminators (green)

### Fixes Along the Way
- Fixed `SYNQ_SERVER` variable not defined for decompile endpoint
- Prevented decompile output from overwriting the contract editor (was destroying user work)
- Equalized Compilation Results pane heights (both 450px) with IR as scroll master for Bytecode pane

## 2. Struct/Tuple Parameter Expansion

### Named Structs (e.g. `Point{x, y}`)
- IDE now expands struct-typed parameters into individual sub-field inputs
- `compileStructDefs` from compile response drives field rendering
- Server returns struct definitions (name + fields with types) in compile response

### Anonymous Tuples (e.g. `(u256, u256)`)
- `parseTupleType()` detects tuple syntax and renders sub-field inputs by arity
- Server accepts comma-separated strings (`"10, 20"`) and JSON arrays (`[10, 20]`) as tuple values

### Bug Fixes
- `paramsContainer` ReferenceError — variable was `grid` not `paramsContainer`
- `.toLowerCase()` broke `lookupStructDef` — struct names are case-sensitive
- `struct_defs` not merged from server cross-check into WASM compile path
- Double commas from sed global replace in param collection
- Server rejected single-value args for tuple-typed params (now validates arity)

## 3. State Bar Struct Display

### Before
```
corner = [2 items] │ box_val = [2 items] │ initialised = true
```

### After
```
corner = Point{x:10, y:20} │ box_val = Rect{origin:(x:1, y:2), size:(x:100, y:200)} │ initialised = true
```

- Uses `compileStructDefs` to expand arrays into named fields
- Handles **nested structs recursively** (e.g. `Rect` contains two `Point` fields)
- Falls back to `[v1, v2]` for anonymous tuples without a struct definition
